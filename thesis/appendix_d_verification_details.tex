The cognitive cases cover selected positive paths and one precedence condition. They do not systematically test every pattern combination, tie, negation, quotation, malformed clause, dialect, or correction of a wrong inference. The appropriate result is rule conformance rather than accuracy.

The twelve-case lexical-extraction fixture produced five true positives, four true negatives, one false positive, and two false negatives. The seven affect-pacing cases covered confident agreement, disagreement, low confidence, missing audio, unavailable inference, disabled adaptation, and explicit preference; all seven matched the declared action. Safety, task completion, study eligibility, and required-task status were tested as higher-priority guards.

\section{Automated, Full-Stack, and Accessibility Evidence}

The final backend suite collected 258 cases, with 245 passes and 13 skips from the opt-in real-MongoDB module. All skips reported that the real-database test URI was not configured. Ruff, the production frontend build, and frontend linting passed. The browser suite executed 38 logical cases in both desktop Chromium and a Pixel~7 profile, producing 76 passes.

Ten interface states were scanned in both profiles with axe-core rules mapped to WCAG~2.0 and 2.1 Levels A and AA. All 20 scan executions returned no detected violation. The result covers the exercised DOM states and automated rules only; it is not a WCAG certification.

Two full-stack journeys ran against a compiled frontend, FastAPI process, and disposable MongoDB~8.0.1 instance. They covered account access, pre-consent exclusion, enrolment, a required task and questionnaire, export, enhanced dialogue, network-failure recovery, replay, branching, comparison, and action-card persistence. State was verified after two backend restarts. Providers and trained inference were disabled.

\section{Local Performance Detail}

The local benchmark used FastAPI's in-process transport and memory repository. It included routing, authentication, request validation, services, and response serialisation, but excluded network transit, MongoDB, providers, trained inference, and concurrent clients. Read-only endpoints used 200 post-warm-up samples and state-changing operations used 100.
